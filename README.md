# 週末キッズクイズ（こどもの あそびば）

子ども向けの学習・あそびサイトです。トップページは年齢別の3つのドア（7さい／3さい／ゲーム）に分かれています。
中心コンテンツの「週末キッズクイズ」は、小学2年生向けの週末5分で遊べるクイズで、毎週土曜に新しい回が追加されます（週次タスクもブランチ→PR→CI→マージのフローで公開）。

公開URL: https://latte0088.github.io/weekly-kids-quiz/

## ファイル構成

- `index.html` — トップページ（「7さい」「3さい」「ゲーム」のドアカード）
- `games/index.html` — ゲームの入り口ページ（ゲームのドアカード一覧）
- `games/star-striker/index.html` — STAR STRIKER（宇宙シューティング。単一ファイル、Canvas＋Web Audio。ドラッグ／マウスで移動、タッチ中オートショット、コンボ・パワーアップ・ボス戦、ハイスコアは localStorage 保存）。ボスは倒すたびに形態変化する：形態1〜3は色だけ変化（赤→オレンジ→紫）、4で両翼＋ウイングキャノン、5でツノと回転シールド、6でサブコア×2（壊すと各50点）、7以降は大型化
- `games/runner/index.html` — ポヨンラン（7歳向けオートラン横スクロールアクション。単一ファイル、Canvas＋Web Audio、横画面前提・縦画面は案内表示。全画面ボタンつき（全画面中はサイトバーを隠す）。タップでジャンプ／2回で2段ジャンプ（雲エフェクト）、コヨーテタイム0.15秒。ハート3つ制で敵・トゲはダメージ＋2秒無敵、穴はハートを減らして直前の足場から復帰。ギミック：コイン（アーチ配置）、スター3つ、バネ（2倍ジャンプ）、ダッシュ床（3秒間スピードアップ＋虹色・体当たり無敵）、消える雲の足場、踏める敵、トゲ敵、ゴールの旗でクリア＋紙吹雪。表示文字はひらがな・カタカナのみ。ゲームオーバーでは STAR STRIKER と同じく九九チャレンジへ遷移でき、クリアすると1ラン分のパワーアップ（`runnerPowerUp` フラグ＝ハート4つでスタート）がチャージされる。九九側のチャレンジは `challenge` パラメータでゲームごとにフラグと戻り先を切り替える）
- 九九チャレンジ連動（ご褒美方式） — STAR STRIKER のゲームオーバー画面ではロックされず、2つのボタンから自分で選べる：A「✖️ 九九を 10もん といて パワーアップ スタート！🚀」（九九チャレンジへ）、B「🔄 そのまま もういちど あそぶ」（その場で即リスタート）。九九チャレンジ（`kuku/?challenge=star-striker`）は、おすすめの段・10問固定・タイマーは非表示。正解するごとに⚡パワーチャージが貯まり、クリアすると1ラン分のパワーアップ（localStorage `starStrikerPowerUp` フラグ）がチャージされる。タイムは裏で計時され、スピードアタックのベスト記録（おすすめの段×10問）にも反映されるため、チャレンジをクリアするたびにおすすめの段が次へ進む。パワーアップは消費型で、次のラン開始の瞬間に消費され、その1ランだけシールド＋3WAYショット＋アイテムマグネット＋開始時無敵が付く。ゲームオーバーで効果は終わり、パワーアップで遊んだランの終了時には「また 九九で チャージしよう！」のメッセージが出る。[P]アイテムは基礎パターンを1段階引き上げる（通常ラン→3WAY、パワーアップ中→5WAY・弾はピンク色）。スコアは引き継がず、強化された状態での新規ラン（強くてニューゲーム）とする
- 難易度スケーリング — ボスを倒すごとに（`bossLevel`）敵が少しずつ強くなる：出現間隔の短縮、敵の速度・HP上昇（雑魚のHPは据え置き）、強い敵の出現率上昇、アイテムドロップ率上昇、ボスの扇弾の本数増加（弾速は上限つき）。ボス撃破時はステージクリア演出とボーナスアイテムが出る。後半ほど九九のパワーアップの価値が上がる設計
- 九九の「おすすめ」ボタン — ぜんぶ（ミックス）の下にあり、記録が無い組み合わせ（段×10問、段1→9→ミックスの順）を優先し、全部に記録がある場合は1問あたりのベストタイムが最遅の組み合わせを勧める。押すとその組み合わせで即スタートする。20問はおすすめの候補に入らない（長いコースへアプリ側から誘導しないため。自分で選べば遊べる）。計算アプリのおすすめも同仕様
- 九九の「記録クリア」ボタン — スタート画面の最下部（おうちのひと用）。ベスト記録（`kuku-best-*`）を全部消す前に「はい／いいえ」の確認を出す。STAR STRIKER 側の記録やロックには触れない
- `grade2/index.html` — 7歳（小学2年生）向け入り口ページ（「クイズ」「九九」「たしざん・ひきざん」のドアカード）
- `age3/index.html` — 3歳向けアプリ（単一ファイルSPA：選択ハブ＋3ゲーム。外部アセットなし、音はWeb Audio合成）
  - おべんとうづくり：おかず18種（たまごやき・キウイ・ミートボール・えだまめは自作SVGイラスト、ハンバーグは焼き目入りの自作SVG）。4個以上入れると「できた！」が押せ、完成後はタップで1つずつ食べさせる「あーん」フェーズ（全部食べると💮）。プレート切替（通常／新幹線）つき。背の低い画面ではおかずトレイが6列に圧縮され、「できた！」が画面内に収まる
  - どうぶつかくれんぼ：動物10種＋「のりもの」モード。不正解のペナルティなし、星10個で結果画面に進み、ごほうび花火が上がる
  - キラキラはなび：なぞって描くとスタンプが付き、描いた量で花火が増減（最大4発連射）。スタンプは24種。たくさん描いた場合（それ以外は確率）で、貼ったスタンプの中から1種がその色で浮かび上がる変身花火が出る
- `quiz/index.html` — クイズの目次ページ（最新ボタン・ランダムボタン・あそびかた・回の一覧）
- `assets/style.css` — クイズ側の全ページ共通デザイン
- `assets/quiz.js` — クイズ共通のエンジン
- `assets/questions.js` — ランダムモード用の全問プール（`tools/build_questions.py` が各回から自動生成。手で編集しない）
- `quiz/quiz-001.html`、`quiz/quiz-002.html` … — 回ごとのページ（各5問。第1回〜第3回を公開中）
- `quiz/random.html` — ランダム5問モード（全問プールから重ならない5問を毎回ランダム出題）
- `kuku/index.html` — 九九スピードアタック（九九のタイムアタックゲーム）。出題の「でかた」は2モード: ランダム（シャッフル山札方式で、かけられる数（ミックスでは かける数も）が9問ごとに1〜9を一巡し、連続で同じ数字は出ない）と、じゅんばん（昇順: 固定段なら ×1→×9 の繰り返し、ミックスなら 1×1〜9×9 の順）。ベスト記録はモード別（じゅんばんは `kuku-best-jun-*`）に保存し、おすすめの判定は両モードの記録を見る。ゲームからの挑戦（九九チャレンジ）は じゅんばん固定でテンポよく解ける
- `calc/index.html` — たしざん・ひきざんスピードアタック（九九と同じUIの計算タイムアタック）。たしざん／ひきざん／ミックス × 1けた／2けた × 10もん／20もん／エンドレス。1けたの出題はシャッフル山札方式、ひきざんの答えは0以上、ベスト記録はモードごとに保存
- `tests/` — Playwrightによる自動テスト一式（下記）
- `.github/workflows/tests.yml` — GitHub Actions CI（push / Pull Request で自動テスト）

## テスト

Playwright で実際のブラウザを操作して検証します（全15ファイル・76テスト。おべんとうの高速タップ完食と「もういっかい」後の再プレイ・小さい画面でのボタン配置、かくれんぼの星プログレスと乗り物モード、はなびのスタンプパレット（24種）と変身花火、九九の出題方式・おすすめ・○×バッジ位置、計算のモード別記録、クイズ全問正解フロー、ランダムモードの抽選と通しプレイ、STAR STRIKER のボス形態変化とパワーアップ連動、ポヨンランのギミックと九九チャレンジ連動、ページ遷移）。

加えて `tests/security-scan.spec.js` で、公開リポジトリへの機密情報・個人情報の混入を検査します。認証情報パターン（GitHub PAT、秘密鍵、APIキー、パスワード代入など）はリポジトリ全体、連絡先や開発環境の痕跡（メールアドレス、電話番号、郵便番号、ローカルの絶対パス）は公開ページ側ファイルを対象にスキャンし、1件でも見つかればテストが失敗します。検出パターン自体がダミーの秘密情報を捕まえられるかの自己検証も含みます。子どもの名前・学校名のような固有名は、リスト自体を公開できないため対象外で、「個人情報を入れない」運用ルールで担保します。

- ローカル実行: `npm ci` → `npx playwright install chromium` → `npm test`（テスト用サーバーが自動で起動します）
- CI: main への push と Pull Request で GitHub Actions が自動実行します。公開（GitHub Pages へのデプロイ）は従来どおり push で自動反映されます。

## 開発フロー

変更はブランチを作成して行い、CI（Playwrightテスト）が通過してから `main` にマージします（`main` へ直接コミットしません）。毎週土曜のクイズ新回の追加も、週次タスクが同じフロー（ブランチ→PR→CI→マージ）を自動で実行します。
